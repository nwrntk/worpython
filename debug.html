วิธีหาบั๊ก

บั๊ก (bug) คือจุดที่โปรแกรมทำไม่ตรงกับที่เราตั้งใจ · หน้านี้คือวิธีตามหาอย่างเป็นขั้นตอน แทนการเดาแล้วแก้มั่ว ๆ · ผลลัพธ์ทุกอันได้จากการรันจริงด้วย Python 3.13

อาการทำอะไรก่อน
โปรแกรมพัง มีข้อความ error สีแดงอ่าน error ก่อน ดูคู่มืออ่าน error
รันจบ ไม่มี error แต่ผลผิดส่องค่าตัวแปรกลางทาง (หัวข้อ 2–3)
โปรแกรมค้าง ไม่จบสักทีกด Ctrl+C แล้วดูว่าค้างบรรทัดไหน (หัวข้อ 4)

1. ขั้นตอนหาบั๊ก 5 ขั้น

  1. ทำให้เกิดซ้ำได้ · จดว่าใส่ input อะไรแล้วผลผิด ถ้าผิดบ้างถูกบ้าง ให้หา input ที่ผิดทุกครั้งให้เจอก่อน
  2. รู้ว่าผลที่ถูกคืออะไร · คิดด้วยมือก่อนว่าควรได้เท่าไร ถ้าไม่รู้คำตอบที่ถูก จะไม่รู้เลยว่าผิดตรงไหน
  3. ส่องค่าจริงกลางทาง · ใส่ print หรือใช้ debugger ดูว่าตัวแปรเป็นค่าอะไรจริง ๆ ในแต่ละจุด
  4. หาจุดแรกที่ค่าเพี้ยน · ไล่จากบนลงล่าง จุดแรกที่ค่าจริงไม่ตรงกับที่คิดไว้ คือบริเวณที่บั๊กอยู่
  5. แก้ทีละจุด แล้วรันซ้ำ ด้วย input เดิม และลอง input อื่นด้วย เผื่อแก้แล้วไปพังที่อื่น
อย่าเดาแล้วแก้หลายจุดพร้อมกัน ถ้าผลถูกขึ้นมาจะไม่รู้ว่าจุดไหนคือตัวแก้จริง ถ้าผลยังผิดจะไม่รู้ว่าจุดไหนทำให้แย่ลง

2. ใส่ print ส่องค่า

วิธีง่ายที่สุดและใช้ได้ทุกที่ · ตัวอย่าง: นับคนที่สอบผ่าน (50 คะแนนขึ้นไปถือว่าผ่าน) คิดด้วยมือได้ 4 คน แต่โปรแกรมตอบ 3

scores = [80, 45, 92, 50, 68]
count = 0
for s in scores:
    if s > 50:
        count += 1
print("ผ่าน", count, "คน")
# ผ่าน 3 คน   ← ควรได้ 4

ใส่ print ในลูปให้เห็นทุกค่าที่เกี่ยวข้อง · เขียน = ต่อท้ายชื่อใน f-string เช่น f"{s=}" Python จะพิมพ์ทั้งชื่อและค่าให้ ไม่ต้องพิมพ์ชื่อเอง

scores = [80, 45, 92, 50, 68]
count = 0
for s in scores:
    print(f"{s=} {s > 50=} {count=}")
    if s > 50:
        count += 1
print("ผ่าน", count, "คน")
s=80 s > 50=True count=0
s=45 s > 50=False count=1
s=92 s > 50=True count=1
s=50 s > 50=False count=2
s=68 s > 50=True count=2
ผ่าน 3 คน

บรรทัด s=50 s > 50=False คือจุดแรกที่ค่าเพี้ยนจากที่คิด: 50 ควรผ่านแต่เงื่อนไขได้ False · แก้เป็น s >= 50 แล้วลบ print ที่ใส่ส่องออก

ดูทีละบรรทัด · ตามหาคนที่หายไป

โค้ดเดียวกับข้างบน · กด "ถัดไป" แล้วจับตาตอน s เป็น 50 ว่าเงื่อนไขได้ True หรือ False

เคล็ดลับ print
ถ้าสงสัยชนิดข้อมูล ใช้ print(type(x), repr(x)) · repr ทำให้เห็นว่า '5' เป็นข้อความ ไม่ใช่ตัวเลข 5 และเห็นช่องว่างที่ติดมากับข้อความด้วย
ใส่ print ก่อนและหลังจุดที่สงสัย จะรู้ว่าค่าเปลี่ยนเพราะบรรทัดไหน

3. ใช้ debugger ใน VS Code

debugger ทำแบบเดียวกับตัว "ดูทีละบรรทัด" ในบทเรียน แต่ใช้กับโค้ดของเราเองได้ ไม่ต้องใส่ print ต้องมี extension Python ตามบทที่ 0 (ติดตั้ง Python Debugger มาให้ด้วยแล้ว)

  1. ตั้ง breakpoint: คลิกที่ว่างซ้ายเลขบรรทัดที่อยากให้หยุด จะมีจุดแดง ขึ้น (หรือวางเคอร์เซอร์แล้วกด F9) · ตัวอย่างนี้ตั้งที่บรรทัด 4 if s > 50:
  2. เริ่ม debug: กด F5 แล้วเลือก Python Debugger → Python File โปรแกรมจะรันแล้วหยุดที่ breakpoint (บรรทัดนั้นยังไม่ได้ทำ)
  3. ดูค่า: แผง VARIABLES ด้านซ้ายแสดงค่าทุกตัวแปรตอนนั้น หรือเอาเมาส์ไปชี้ชื่อตัวแปรในโค้ด
  4. เดินต่อ: ใช้ปุ่มบนแถบเครื่องมือหรือคีย์ลัดตามตารางด้านล่าง

4. โปรแกรมค้าง: loop ไม่จบ

กด Ctrl+C ใน Terminal เพื่อหยุด · Python จะบอกว่าตอนที่หยุดกำลังทำบรรทัดไหน ซึ่งมักอยู่ในลูปที่วนไม่จบ

n = 1
while n <= 5:
    print(n)
n += 1
print("จบ")

สาเหตุ: n += 1 ย่อหน้าออกมานอกลูป ค่า n จึงเป็น 1 ตลอด เงื่อนไขจริงตลอดไป
แก้: ย่อหน้า n += 1 ให้อยู่ในลูป · ถามตัวเองทุกครั้งที่เขียน while: บรรทัดไหนทำให้เงื่อนไขเป็นเท็จได้ในที่สุด?

5. บั๊กที่เจอบ่อย เช็กก่อนเลย

อาการมักเกิดจาก
ขาดไป 1 ตัว หรือเกินมา 1 รอบ> กับ >= · range(1, n) ไม่รวม n · slice ไม่รวม stop
พิมพ์ซ้ำหลายบรรทัด / ได้ผลแค่รอบสุดท้ายย่อหน้าผิดชั้น: บรรทัดควรอยู่นอกลูปแต่อยู่ใน หรือกลับกัน
ผลรวมได้แค่ค่าสุดท้ายตั้ง total = 0 ไว้ในลูป ค่าจึงถูกล้างทุกรอบ
ฟังก์ชันดูแค่ตัวแรกแล้วเลิกreturn อยู่ในลูป (ดูโจทย์ข้างล่าง)
ต่อข้อความแทนบวกเลข เช่น "5" + "3" ได้ 53ลืมแปลง input() เป็น int()
ค่าติดลบ / ศูนย์ ให้ผลแปลกค่าเริ่มต้นเดาไว้ผิด เช่น เริ่มหาค่ามากสุดจาก 0

ดูตัวอย่างเพิ่มในไม่มี error แต่ผลผิด

แบบฝึก · ตามหาบั๊ก 2 ตัว

โจทย์ — ฟังก์ชันหาค่ามากสุด

ควรได้ 8 กับ -2 แต่ได้ผลตามด้านล่าง · ใช้ print หรือ debugger หาให้เจอว่าผิดตรงไหน (มี 2 จุด แก้จุดแรกแล้วจะเจอจุดที่สอง)

def find_max(nums):
    biggest = 0
    for n in nums:
        if n > biggest:
            biggest = n
        return biggest

print(find_max([3, 8, 5]))
print(find_max([-4, -2, -9]))

0

# บั๊ก 1: return อยู่ในลูป → ดูตัวแรกแล้วคืนค่าเลย ได้ 3
# บั๊ก 2: เริ่ม biggest = 0 → ถ้าทุกตัวติดลบ ไม่มีตัวไหนมากกว่า 0 เลยได้ 0
#         แก้โดยเริ่มจากสมาชิกตัวแรกของ list
def find_max(nums):
    biggest = nums[0]
    for n in nums:
        if n > biggest:
            biggest = n
    return biggest

print(find_max([3, 8, 5]))
print(find_max([-4, -2, -9]))
# 8
# -2
